# 管理员地图按农户县区高亮方案

## 目标

管理员地图将来通过数据库查询出“有农户分布的县区”，只让这些县区正常显示，其他区域统一弱化显示。

当前地图已经有：

- 市级 GeoJSON
- 县区级 GeoJSON
- 按缩放切换图层

后续要补的是“数据库结果驱动地图渲染”这一层。

---

## 总体思路

这不是单纯的地图功能，核心是：

1. 后端查出有农户的县区
2. 前端拿到这些县区的行政区编码
3. 地图渲染时命中的区域正常显示
4. 未命中的区域弱化显示

建议始终使用 `adcode` 作为地图和数据库之间的关联键，不要只依赖中文名称。

---

## 推荐数据结构

后端接口返回建议如下：

```json
{
  "districts": [
    { "adcode": "410102", "name": "中原区", "farmer_count": 12 },
    { "adcode": "410103", "name": "二七区", "farmer_count": 7 }
  ]
}
```

前端接收后维护两个集合：

```dart
Set<String> _activeDistrictAdcodes = {};
Set<String> _activeCityAdcodes = {};
```

含义：

- `_activeDistrictAdcodes`
  - 有农户的县区集合
- `_activeCityAdcodes`
  - 由县区集合反推得到的市级集合

---

## 为什么要同时维护市级和县区级集合

当前地图有两份 GeoJSON：

- 市级图层
- 县区级图层

缩小时显示市级：

- 如果某个市下存在任意一个活跃县区，则该市正常显示
- 否则该市弱化显示

放大后显示县区级：

- 命中 `_activeDistrictAdcodes` 的县区正常显示
- 其他县区弱化显示

所以市级集合最好由县区集合派生，而不是单独查一次。

---

## 前端渲染规则

每个区域建议分三档：

### 1. 当前选中区域

- 填充色最明显
- 边框最明显
- 标签正常显示

### 2. 活跃区域

- 正常填充
- 正常边框
- 正常标签

### 3. 非活跃区域

- 填充色透明度降低
- 边框颜色变浅
- 标签变浅或隐藏

判断顺序建议：

1. 是否当前选中
2. 是否属于活跃集合
3. 否则弱化

---

## 与现有代码的对应关系

后续接入时主要改这几个点：

### 1. 页面状态

在管理员地图页增加：

```dart
Set<String> _activeDistrictAdcodes = {};
Set<String> _activeCityAdcodes = {};
```

### 2. 地图面渲染

在 `_buildMapPolygons()` 中：

- 市级图层判断 `_activeCityAdcodes`
- 县区图层判断 `_activeDistrictAdcodes`

### 3. 标签渲染

在 `_buildLabelMarkers()` 中：

- 活跃区域显示正常标签
- 非活跃区域标签弱化或不显示

### 4. 点击交互

点击某一区域时：

- 如果该区域属于活跃集合，则按正常高亮逻辑显示
- 如果不属于活跃集合，可以继续允许点击，但维持弱化风格，或者直接不响应

---

## 后端和数据库要求

### 最理想字段

农户表最好直接保存：

- `province_adcode`
- `city_adcode`
- `district_adcode`

### 如果当前没有 adcode

需要补一层“名称 -> adcode”的映射。

原因：

- GeoJSON 是按 `adcode` 组织的
- 名称可能存在别名、简写、历史名称差异

如果只拿中文名称去匹配，后续容易出错。

---

## 推荐接口职责划分

### 后端负责

- 查询哪些县区存在农户
- 返回县区 `adcode`
- 可选返回统计值，例如 `farmer_count`

### 前端负责

- 读取本地 GeoJSON 几何数据
- 根据 `adcode` 决定哪些区域高亮、哪些区域弱化
- 按缩放级别切换市级/县区级图层

不要让后端把整份 GeoJSON 回传给前端，没必要。

---

## 推荐实现流程

### 第一步

先确认数据库是否能拿到县区 `adcode`。

### 第二步

如果没有 `adcode`，先补映射表或标准化字段。

### 第三步

管理员页面加载时请求接口，例如：

```http
GET /admin/farmer-regions
```

### 第四步

前端拿到结果后：

1. 填充 `_activeDistrictAdcodes`
2. 根据县区 GeoJSON 的 `parentAdcode` 派生 `_activeCityAdcodes`
3. 按当前缩放级别渲染对应图层

---

## 风险点

### 1. 行政区名称不统一

例如：

- “济源市”
- “济源示范区”
- “济源产城融合示范区”

这种情况下必须统一到 `adcode`。

### 2. 农户地址只存到市级

如果数据库没有县区粒度，就只能先做市级高亮，不能精确到县区。

### 3. GeoJSON 和数据库行政区版本不一致

需要确认：

- 数据库里的行政区编码版本
- GeoJSON 的行政区编码版本

最好统一来源。

---

## 结论

后续最稳的做法是：

1. 后端查出“有农户的县区 adcode 集合”
2. 前端本地 GeoJSON 负责几何
3. 市级图层由县区结果派生出哪些市要亮
4. 县区图层按 adcode 精确高亮
5. 其他区域统一弱化显示

这是当前项目后续最适合的实现方式。
